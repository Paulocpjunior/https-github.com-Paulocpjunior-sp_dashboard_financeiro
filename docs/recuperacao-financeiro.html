Anexos e recuperação do Financeiro

O pacote prepara um bucket exclusivo gen-lang-client-0888019226-finance-attachments, em us-central1, para anexos nativos. Acesso público bloqueado, IAM uniforme, versionamento e recuperação de exclusões por 30 dias. O serviço recebe criação e leitura no bucket; permissões já herdadas no projeto não são removidas por este procedimento. Não altera o bucket compartilhado atual.

Ativação protegida

Após PR, testes e autorização de Paulo para o SHA completo, usar o checkout desse commit na main, executar build e guard. A variável FINANCEIRO_APPROVED_COMMIT deve conter exclusivamente o SHA autorizado. Executar npm run attachments:apply. O script reutiliza o digest da imagem em produção e preserva os segredos e demais variáveis do serviço. Em seguida validar configuração, upload e download de um PDF sintético pelo fluxo do app, sem criar despesa fictícia em produção. Se necessário, homologar primeiro o armazenamento com um objeto técnico separado; isso não substitui o teste do fluxo autorizado.

Backup identificável

  1. Executar npm run backup:firestore. Se abortar, não continuar usando outra cópia por suposição.
  2. Usar o caminho exato impresso pelo comando seguinte:
    npm run backup:recovery -- --firestore /caminho/exato.json --bucket gen-lang-client-0888019226-finance-attachments --out /diretorio/novo
  3. O diretório é privado (0700) e os arquivos são restritos (0600). Contém contas e hashes de autenticação: não enviar por e-mail, não versionar e não publicar.

O manifesto inclui checksums SHA-256, o instante do Firestore, gerações dos objetos nativos e a configuração Auth. Os serviços são capturados em instantes distintos. A exportação interrompe a conclusão se faltar um anexo referenciado. Arquivos externos do Jotform, OAuth de provedores, cofres, configurações IAM e replicação externa não estão incluídos. Configuração Auth ausente é uma limitação explícita, nunca prova de recuperação de senha.

Ensaio isolado

Subir Firestore e Auth Emulator com o projeto demo-financeiro-restore e hosts 127.0.0.1. Executar npm run restore:drill -- /pacote/manifest.json. O script recusa destinos remotos e usa criação sem sobrescrita. Verifica até três documentos por coleção/subcoleção, preservando tipos, e importa as identidades Auth. Compara os arquivos restaurados localmente. O relatório registra contagens e limites; não testa senhas reais nem certifica uma restauração integral. Encerrar os emuladores descarta os dados em memória.

Evidência de 10/10/2026

Backup tipado: 181.549 documentos. Ensaio local: 53 documentos e 11 contas restauradas, zero gravações em produção. Nenhum anexo nativo foi encontrado no bucket compartilhado consultado; teste real de objeto no novo bucket depende da ativação. Backup externo agendado e teste integral permanecem próximos passos.

Referências: exportação e importação Auth; versionamento; recuperação de exclusões.
